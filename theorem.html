Section 06 of 07

The 3k-vertex kernel theorem

Theory notes

Finding a crown in a large graph

The goal is a linear kernel: reduce every yes-instance to at most 3k vertices, where k is the cover budget. If the graph has more than 3k vertices, we either certify that no cover of size k exists or find a crown that can be safely removed. A large matching gives the certificate. If the matching is small, there are many unmatched vertices, which we use to construct the crown.

Crown-finding lemma

Lemma. If |V(G)|>3k, then in polynomial time we can either certify that G has no vertex cover of size at most k, or find a crown (C,H,R) with |C|>|H|.

Step 1: find an independent set of unmatched vertices. Find a maximal matching M greedily. If |M|>k, its disjoint edges require more than k cover vertices, so reject. Otherwise, let I be the unmatched vertices. Maximality ensures I is independent: an edge between two unmatched vertices could be added to M. Also, |I|=|V(G)|-2|M|>3k-2k=k.

Step 2: match the independent set to the rest. Build the bipartite graph with left side I, right side V(G)∖I, and all original edges between the two sides. Find a maximum matching M′ in polynomial time, for example with Hopcroft–Karp. If |M′|>k, then M′ itself is a matching of more than k edges in G, so reject. Otherwise, since |I|>k≥|M′|, at least one left-side vertex is unmatched.

Step 3: follow alternating paths. Starting at every unmatched vertex on the left, traverse nonmatching edges from left to right and matching edges from right to left. Let C be the reached vertices on the left and H the reached vertices on the right. No reached right-side vertex can be unmatched, or there would be an augmenting path for M′, contradicting that M′ is maximum. Thus every vertex of H is matched to a distinct reached vertex of C. Every neighbor of a reached left-side vertex is reached, so H=N(C). Finally, at least one reached left-side vertex is unmatched; therefore |C|>|H|. Since C⊆I, it is independent. These properties make (C,H,R), with R=V(G)∖(C∪H), a crown. ∎

The 3k-vertex kernel theorem

Theorem. Vertex Cover has a polynomial-time kernelization that either correctly rejects (G,k) or returns an equivalent instance with at most 3k vertices.

Algorithm. Remove isolated vertices. While |V(G)|>3k, apply the lemma. If it rejects, reject. Otherwise use the crown-reduction theorem: include H in the cover, delete C∪H, and replace k by k-|H|. If the new budget is negative, reject. Because |C|>|H|, the set C is nonempty, so every crown reduction removes at least one vertex.

Correctness. Each matching larger than the current budget is a valid no-certificate. Removing isolated vertices preserves the answer, and each crown reduction preserves it by the preceding theorem. Thus every step either correctly rejects or leaves an equivalent instance.

Size bound. The process stops when the remaining graph has at most 3k′ vertices, where k′ is the current budget. The budget only decreases, so k′≤k, and the final graph has at most 3k vertices.

Running time. Each crown removes at least one vertex, so there are at most n iterations. Each iteration finds matchings in polynomial time. The full preprocessing is therefore polynomial-time. ∎

When the current graph has more than 3k vertices, the algorithm either finds a matching larger than the budget and rejects, or uses alternating reachability to find a crown. Reducing the crown preserves the answer, lowers the budget, and removes vertices from the graph.

Why the bound is useful

The quadratic kernel in the preceding section may leave as many as 2k2 vertices, while this theorem leaves at most 3k. The coefficient 3 comes from the threshold in the crown-finding lemma. For fixed-parameter tractability, either bound is useful: once the kernel is small, we can run a search algorithm on it. The linear bound is stronger because it leaves a smaller instance as k grows.
