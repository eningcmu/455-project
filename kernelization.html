Kernelization and a quadratic kernel

Theory notes

Preprocessing and kernelization

Branching searches through possible choices of cover vertices. Kernelization takes a different approach: simplify the graph before searching, while preserving the answer.

For a parameterized problem Q, an answer-preserving preprocessing algorithm maps an instance (x,k) in polynomial time to an instance (x′,k′) such that (x,k)∈Q exactly when (x′,k′)∈Q. This preserves the yes/no answer but, by itself, places no bound on the output size.

Kernelization. A kernelization is an answer-preserving polynomial-time algorithm that maps each parameterized instance (x,k) to an equivalent instance (x′,k′) satisfying |x′|+k′≤g(k) for some computable g. The output is a kernel. Every kernel has a parameter-dependent size bound, but that bound need not be polynomial. A polynomial kernel has a polynomial bound in k; a linear kernel has an O(k) bound.

For graph problems, results are often stated structurally, such as “at most 3k vertices.” For a simple graph this implies a polynomial encoding-size bound, since it has at most O(k2) edges.

FPT and kernelization

Theorem. Every decidable parameterized problem with fixed yes- and no-instances is FPT if and only if it admits a kernelization.

Proof sketch. A kernel of size g(k) can be decided by a terminating decider in time bounded by a computable function of k, in addition to the polynomial kernelization time, giving an FPT algorithm.

Conversely, suppose an FPT algorithm runs in time f(k)Nc. Simulate it for (N+1)d+1 steps, where d≥c is an integer. If it halts, output a fixed yes- or no-instance according to its answer. If not, return the original instance; the running-time bound then implies N<f(k). This is a polynomial-time answer-preserving preprocessing with output size bounded by a function of k. ∎

This equivalence guarantees some kernel for every FPT problem, but not a polynomial kernel. The following Vertex Cover reductions give explicit quadratic and linear bounds.

Safe reduction rules for Vertex Cover

Rule 1: remove isolated vertices. An isolated vertex is not needed in a vertex cover, so deleting it preserves the answer.

Rule 2: force a high-degree vertex. If deg(v)>k, every cover of size at most k must contain v; otherwise all its more than k neighbors would be needed. Include v, delete it and its incident edges, and decrease k by one. This is safe in both directions: every original cover must use v, and adding v to a cover of G−v covers the removed edges.

Rule 3: force the neighbor of a leaf. If u has degree one with unique neighbor v, some minimum cover contains v. If a cover contains u but not v, replace u by v; no edge becomes uncovered because u has no other incident edges. Include v, delete it and its incident edges, and decrease the budget by one.

Apply the safe rules repeatedly until none applies; reject if the budget becomes negative. Each forced choice is recorded so a cover of the reduced graph can be lifted to the original. At this point, the remaining graph has no isolated or degree-one vertices and maximum degree at most the current budget.

The quadratic-kernel theorem

Theorem. In polynomial time, these rules either correctly reject the instance or produce an equivalent instance with at most 2k2 vertices.

Proof. Let k′≤k be the current budget after applying the rules, and let m be the number of remaining edges. Every remaining vertex has degree at most k′. A cover of size at most k′ can therefore cover at most (k′)2 edges: each selected vertex is incident to at most k′ edges, and counting an edge twice only loosens this upper bound. If m>(k′)2, reject. Otherwise, since isolated vertices were removed, every vertex is an endpoint of an edge, so |V(G)|≤2m≤2(k′)2≤2k2. ∎

Record forced vertices so that a cover of the reduced graph can be lifted to the original graph. The quadratic kernel can then be solved directly or passed to the branching algorithm.
